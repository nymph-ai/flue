MCP speaks the stateless 2026-07-28 protocol only, and Code Mode is `@cloudflare/codemode`'s own runtime, a Durable Object Facet of the agent.

**MCP.** The client is `@modelcontextprotocol/client` 2.2.0 again (it replaces `@earendil-works/pi-mcp`), pinned to protocol revision 2026-07-28: a connection probes with `server/discover` and carries no session. There is no fallback to the 2025 `initialize` handshake: a server that does not offer 2026-07-28 is refused with `McpProtocolVersionError`, naming the server and the versions it offered (or its `server/discover` answer). An agent holds nothing open between wakes: no `subscriptions/listen`. Tool lists are refreshed when the server's cache hint (`ttlMs`) expires, otherwise on the next wake. `useMcpConnection()`, `defineMcpConnection()` and `createMcpConnection()` keep their shape, and `McpConnectionDefinition` stays one interface. Changes:

- **Breaking:** servers on protocol revisions before 2026-07-28 are no longer supported, on any target.
- **Breaking:** there is no stdio transport, on any target, Node included. `transport: 'stdio'` fails with an error saying so; serve the server over Streamable HTTP. `transport: 'sse'` (legacy HTTP+SSE) is still refused.
- A connection survives a Durable Object eviction with no saved state. Before, the cached connection stayed broken until the instance was evicted.
- Tool names no longer collide. `mcp__<server>__<tool>` is used as is when both parts are letters, digits, `-` and single inner `_`; any other name gets a stable `__<hash>` suffix, so `get-user` and `get_user` (or a `__` inside a name) stay two tools. `mcpToolName(server, tool)` computes the name.
- Images from MCP tools reach the model as images, not as text placeholders.
- A server answering `input_required` with input requests (an elicitation, a sampling request, the roots list) is asked through the runtime's question seam, and its answers are sent back with the server's `requestState`. The question is published as an entity event and the call waits for the answer (see the questions changeset); without entity streams, the call fails with `McpInputRequiredError` naming what the server asked for. A leg carrying only `requestState` is sent again with it. Flue advertises no elicitation, sampling or roots capability.
- New: `auth: mcpOAuth({ principal, redirectUrl, scope?, clientMetadataUrl?, clientName? })`. Flue discovers the authorization server, registers (a Client ID Metadata Document when the server supports it, dynamic registration with `application_type: "web"` otherwise), runs the authorization-code flow with PKCE, checks `iss` on the callback (RFC 9207), binds every credential to the authorization server's issuer, and refreshes tokens one at a time. A call that needs the user fails with `McpAuthorizationRequiredError`, carrying the authorization URL. Redirects land on `/__flue/mcp/oauth/callback`, served ahead of `app.ts` by the Worker and the Node server. On Cloudflare, credentials live in the `FlueMcpAuth` Durable Object (one per principal and authorization server): `@flue/vite` binds it as `FLUE_MCP_AUTH` when an agent module calls `mcpOAuth(`, and the wrangler config needs a migration with `new_sqlite_classes: ["FlueMcpAuth"]`. On Node, credentials are kept in memory unless `setMcpOAuthBroker(createMcpOAuthBroker({ storage }))` puts them elsewhere.

**Code Mode.** `useCodeMode()` is now `@cloudflare/codemode` 0.5.2's runtime, and runs on the Cloudflare target only:

- The runtime is a Durable Object Facet of each agent (`codemode:flue`), with its own SQLite: the execution log, pending approvals, `codemode.step()` results and snippets. Scripts run in a fresh Dynamic Worker with `globalOutbound: null`.
- The model gets the package's sandbox API: `codemode.search(query)` / `codemode.describe(path)` (methods and saved snippets), `codemode.step(name, fn)` (run once, replay on resume), `codemode.run(name, input)` (saved snippets), plus `codemode.store(key, value)` / `codemode.load(key)`, kept per conversation in a Pi document. `tools.<name>(input)` calls the agent's own tools; each MCP server is an `McpConnector`, `<server>.<method>(input)`.
- New: `useCodeMode({ requiresApproval })` — sandbox paths (`'github.create_issue'`, `'github.*'`) or a predicate over each method, which sees the MCP server's annotations. The runtime pauses the execution at such a call and continues it by replay once the question is answered (approve or reject). Approvals are questions published as entity events (see the questions changeset).
- New: `codemodeRuntime()` from `@flue/runtime/cloudflare/codemode`, inside the agent: `executions()`, `pending()`, and `saveSnippet()` / `snippets()` / `deleteSnippet()` to curate snippets.
- Options are `{ requiresApproval?, executor?, maxOutputTokens? }`; `executor` defaults to `createCodemodeExecutor({ loader: env.LOADER })`, which moved to `@flue/runtime/cloudflare/codemode` (from `@flue/runtime/cloudflare`): `limits: { cpuMs: 30000, subRequests: 1000 }` by default, and at most 4 scripts at once per instance.
- **Breaking:** Code Mode is not available on Node. `NodeCodemodeExecutor` is removed; a Node build of an app that calls `useCodeMode()` fails, naming the module.
- `@flue/vite`: when an agent module calls `useCodeMode(`, the Worker binds `LOADER`, the generated entry exports `CodemodeRuntime` (facets are created from `ctx.exports`; the class needs no binding or migration), and the build fails if the wrangler config sets `disable_ctx_exports` or declares an agent class under `new_classes` (a facet's parent must be SQLite-backed).
- The `CodemodeExecutor`, `CodemodeResult` and related types from `@earendil-works/pi-codemode` are no longer exported; `CodemodeExecutor` is now `@cloudflare/codemode`'s `Executor` contract.
